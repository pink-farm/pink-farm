# Pink Farm security review

## Scope and posture

This review inspected the Next.js 16.4.0 application routes, Proxy, authentication utilities, Prisma MongoDB schema, seed behavior, checkout, customer ownership paths, admin operations, and deployment configuration. It includes limited, non-destructive GET checks against the owner-provided Vercel deployment. No credentials, payment actions, production database operations, destructive tests, or uncontrolled scans were used. This is not a complete penetration test.

The initial source had no effective admin Proxy check, a 365-day stateless session lifetime, a hardcoded administrator email despite a documented environment setting, no login throttling, and checkout code that marked orders paid while fabricating a payment reference despite online payments being disabled.

## Findings and changes

| Finding | Severity | Remediation | Verification | Remaining work |
| --- | --- | --- | --- | --- |
| Admin Proxy unconditionally allowed every `/admin` request | High — the owner-provided deployment currently returns the admin dashboard to an unauthenticated GET | Workspace Proxy validates the signed admin session and redirects missing/invalid sessions; the protected layout and APIs enforce authorization | Local unauthenticated `/admin` redirected to `/login`; live no-cookie GET returned `200` and contained admin dashboard markers (body not printed or retained) | Urgent: release the reviewed workspace fix through the approved deployment process, then recheck `/admin` and authenticated admin flows |
| Sessions lasted 365 days and accepted a fallback JWT secret | High | Admin lifetime is 8 hours with a 20-minute server-enforced idle timeout; customer lifetime is 30 days; production requires `SESSION_SECRET`; JWT algorithm, issuer, audience, signature, and expiry are verified | TypeScript pass; 20-minute idle policy unit test; lint pass | Database-backed activity and expiry behavior still needs isolated integration testing |
| Logout only removed the browser cookie | Medium | Tokens receive unique IDs and logout writes a server-side revocation record; admin/customer session checks reject revoked IDs | TypeScript pass; source inspection | Requires the additive `AuthRateLimit` collection; database integration tests unavailable |
| Admin identity configuration was hardcoded and ignored `ADMIN_EMAIL` | High | Authentication and Proxy share normalized `ADMIN_EMAIL`; the legacy identity is a development-only default, production fails closed without explicit configuration, admin login/OTP/recovery resolve the account on the server, and client pages no longer bundle the administrator email | Policy tests; TypeScript and lint | Confirm configured email matches the intended administrator before seeding |
| Authentication endpoints had no effective shared login throttling | High | MongoDB fixed-window throttles cover admin/customer password login, OTP send/verify, and password reset; trusted Vercel deployments also apply source-IP limits; production fails closed if unavailable | TypeScript pass; schema validation | Apply the additive Prisma schema update before deploying; non-Vercel hosting uses account-based limits only |
| Cross-origin state-changing requests had no explicit origin check | Medium | Cookie-authenticated mutations and checkout reject mismatched `Origin` and Fetch Metadata `cross-site` requests | Node policy tests and targeted route lint | Verify through the public deployment proxy |
| OTP verification could race concurrent requests | Medium | OTP and password reset claims use a conditional atomic update before creating a session or changing credentials | TypeScript pass; source inspection | Database concurrency integration test pending |
| Checkout trusted fallback product selection, defaulted invalid quantities and fabricated delivery data | High | Checkout rejects unknown products/options, invalid quantities, missing delivery data, and unavailable catalog items; prices and discounts are recalculated from database records; combo qualification is server checked | TypeScript pass; targeted ESLint pass | No integration tests available; confirm existing products have synchronized variant stock |
| Checkout reported orders as paid without gateway confirmation | Critical | Checkout now creates COD orders as pending payment and no longer fabricates gateway payment IDs; UI describes COD and validates delivery data before submission | TypeScript pass; source inspection | Online payment remains disabled and needs a separate implementation/review |
| Short historical order identifiers made public bearer order pages easier to guess | Medium | New order numbers use 128 bits of randomness; references shorter than that now require the owning customer session for storefront and receipt pages | Node policy tests and source inspection | New order references remain bearer capabilities; users should avoid sharing them |
| Security headers were missing | Medium | Added nosniff, frame denial, strict referrer policy, restricted permissions policy, production HSTS, COOP/CORP, and a Content Security Policy (inline scripts remain allowed for current framework rendering; eval is allowed only in development) | Lint and type checks pass | Verify response headers and check CSP reports through the deployed CDN; tighten inline-script policy after nonce support is implemented |
| Product administration, coupons, and reverse-geocoding exposed exception details | Medium | Product APIs return classified generic errors; coupon validation only exposes exact reviewed messages; geocoding validates bounded coordinates, encodes URL parameters, applies a timeout, and returns a generic upstream failure | Policy tests and route checks | Exercise with isolated database and provider integration |
| JSON APIs accepted unbounded or malformed request bodies | Medium | Shared streamed JSON reader enforces JSON content type, strict parsing, and per-route byte limits for checkout, authentication, admin mutations, customer profile/addresses, feedback, and coupon validation; oversized requests are rejected before parsing | Policy regression tests, lint, and TypeScript | Confirm hosting proxy body limits and exercise each route in preview |
| API and server-rendered error logs could serialize provider, database, or customer details | Medium | Centralized server error logging records only a validated event name, exception class, and safe error code; browser logs omit exception objects | Policy regression tests and lint | Review logs in the deployment platform and apply retention/access controls |

All admin mutation and read APIs inspected enforce `requireAdminSession`; customer profile, address, order history, and cancellation APIs bind records to the signed customer ID. Customer sessions cannot satisfy admin role checks.

## Required deployment configuration

| Variable | Development | Preview/production | Purpose |
| --- | --- | --- | --- |
| `DATABASE_URL` | Required | Required | MongoDB connection string; use a dedicated application database/user with least privilege and restricted network access |
| `SESSION_SECRET` | Optional local fallback only | Required, at least 32 characters | Signs sessions, hashes OTP codes, and protects rate-limit identifiers; rotate to invalidate all existing sessions and OTPs |
| `ADMIN_EMAIL` | Optional local legacy fallback | Required | Normalized owner/admin account email; production admin login, OTP, recovery, and seeding fail closed unless explicitly configured |
| `ADMIN_PASSWORD` | Seed only | Seed only | Initial admin password; at least 16 characters; never expose to client-side variables |
| `BREVO_API_KEY` | Required for OTP/reset email | Required | Brevo transactional email API |
| `BREVO_FROM_EMAIL` | Required for OTP/reset email | Required | Verified sender address |
| `BREVO_FROM_NAME` | Optional | Optional | Sender display name |
| `RAZORPAY_*` | Not used | Not used | Online payment is disabled; these variables do not enable it |

Before deploying, back up the database, review and apply the additive `AuthRateLimit` Prisma model with `npm run db:push`, generate Prisma Client, seed the authorized administrator only after confirming `ADMIN_EMAIL`, and verify auth, logout, throttling, checkout, and response headers in a preview environment. Never run destructive schema commands or deploy this change without an approved release and rollback plan.

Local environment presence check (values were not displayed): `DATABASE_URL`, `SESSION_SECRET`, and Brevo key/sender variables are present; `ADMIN_EMAIL` and `ADMIN_PASSWORD` are absent. Configure the real administrator identity and seed password in the intended deployment secret store before provisioning an admin. The local server also reported MongoDB unavailable during HTTP smoke checks and served fallback public settings; no database-backed behavior was treated as verified.

## Remaining risk register

1. **High — deployment schema not applied:** authentication will fail closed with `503` until the `AuthRateLimit` model exists in the target MongoDB database. Back up, review, then apply the additive schema change in preview and production.
2. **High — production configuration unverified:** set and verify MongoDB, session, administrator, and Brevo variables in each deployment environment. Rotate any credentials previously committed or shared outside the secret manager.
3. **High — development lint dependency advisory:** full npm audit reports the `braces` denial-of-service advisory in the Next ESLint plugin dependency chain. It is development-only and not included in production dependencies. Reassess when a compatible upstream fix becomes available.
4. **Medium — hosting-specific IP limit:** trusted source-IP throttling is enabled only when `VERCEL=1`, where the platform overwrites `X-Forwarded-For`; other hosting environments get account-based limits until their trusted proxy is configured. [Vercel documents this header behavior](https://vercel.com/docs/headers/request-headers).
5. **High — database integration suite:** add tests for database-backed throttling, revoked tokens, route authorization, customer ownership, and stock/coupon transactions against an isolated test database.
6. **Medium — durable security event coverage:** login, rate-limit, session-revocation, authorization-failure, and password-reset events use structured application logs, but a durable audit trail for every sensitive administrator change is not implemented.
7. **Medium — public bearer order pages:** new references are 128-bit bearer capabilities; customers should keep them private. Historical short references now require the owning customer session.
8. **Informational — payments disabled:** only COD is supported. Razorpay verification code is not part of an enabled checkout flow and needs a separate security review before activation.

**Readiness:** not production-ready. The deployed `/admin` page currently returns administrator dashboard markup without authentication. The workspace contains the fix, but the user-provided brief prohibits automatic deployment. Urgent release through the approved deployment process and an unauthenticated live retest are required. The complete build, clean install, and production dependency audit now pass in the isolated copy. Remaining gates include a clean GitHub CI run, review of the development-only high advisory, applying the additive database schema to the intended environment, explicitly configuring admin identity and production secrets, exercising database-backed flows in an isolated preview, and releasing the admin fix through the approved process followed by a deployment smoke check. No production database or deployment was changed.
